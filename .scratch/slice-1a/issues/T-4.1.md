# T-4.1  Split AppModel into three tested types

file: Swiper/ViewModels/AppModel.swift and three new files in the same directory
spec: —
blocked_by: all of Phase 1 and T-3.1
done_when: AppModel is a thin composition root and each new type has unit tests

## Why
`AppModel` is 326 lines, `@MainActor ObservableObject`, and simultaneously owns Route,
authorisation, LibraryOrder, SessionEngine, the store, statistics, effect execution,
PhotoKit change observation, and favorite serialisation. It is the only file with no
tests and the only one where in-flight state races itself (T-1.4).

## Required change
Split into three types with narrow interfaces:
  - SessionController   — owns SessionEngine + effects + persistence
  - LibraryCoordinator  — owns LibraryOrder + the PhotoKit change observer
  - DeletionCoordinator — owns commit, confirmation and statistics
`AppModel` keeps `Route` and composes the three. Keep `SwiperKit` untouched.

Add unit tests for each against `InMemorySessionStore` and `FakePhotoLibrary`.

## Escape hatch
If the split cannot be done without changing `SwiperKit`, STOP and report why. Do not
force it. A report explaining the coupling is a valid outcome of this ticket.

## Do not
change the engine, the views' public surface, or the persistence format. One commit.

## Report
The new file list, each type's tests and their real output, `git diff --stat`, or the
coupling that blocked it.
