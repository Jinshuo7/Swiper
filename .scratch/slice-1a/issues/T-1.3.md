# T-1.3  A swipe is silently dropped while a favorite is in flight

file: Swiper/ViewModels/AppModel.swift
spec: SPEC 3.3
blocked_by: T-0.1
done_when: the chosen policy is implemented and the choice is recorded in the code

## Verbatim SPEC clause
> 3.3  swipe left → queue for deletion and advance; swipe right → keep and advance.

## The decision (this is the actual work — the edit is small)
In `apply(_:)`:
    guard favoriteTask == nil else { return }
A decision made while a `setFavorite` write is in flight is discarded with no feedback.
The user swiped; nothing happened.

Choose ONE and implement it:
  (a) Serialise: queue the pending decision and apply it when the favorite completes.
  (b) Block: make the gesture impossible while `favoriteTask != nil` (the control is
      disabled and the swipe is not recognised), so nothing is silently lost.
  (c) Surface: apply the drop but tell the user.

Recommendation, unless you find evidence against it: (b). It is the smallest change, it
has no queue to get wrong, and "the control is momentarily unavailable" is honest
behaviour. (a) risks reordering decisions against the engine's undo stack.

State your choice in a one-line comment above the guard, with the reason.

## Do not
change `applyFavorite()`, the engine, or any view other than what option (b) requires.

## Report
Your choice and reasoning, the real output of the changed test, `git diff --stat`.
