# T-1.1  Tumbler + undo permanently skips an asset

file: SwiperKit/SessionEngine.swift, SwiperKitTests/SessionEngineTests.swift

blocked_by: T-0.1
done_when: a new test fails on the current code and passes after the fix

## Verbatim SPEC clause
> 5.4  Tumbler never repeats an asset within a session.

## Required change
`undo()` requeues `entry.displacedAssetID` (the asset `advance()` had just consumed) but
never requeues `entry.assetID` — the asset the user is returning to. That asset stays in
`TumblerPlan.handled` and out of `remaining`, so it can never be served again. The
session can therefore finish without ever visiting it.

The existing `testTumblerUndoRequeuesTheDisplacedPhoto` passes because it only checks the
NEXT asset, not coverage of the whole library.

## Failing test to write first
tumbler session over a 5-asset library, fixed seed:
  keep → keep → undo → keep until finished
assert: the set of assets presented equals the whole library, each exactly once.

## Do not
touch the sequential (non-tumbler) undo path, `UndoStack`, or any view.

## Report
The failing run first (real output), then the passing run, `git diff --stat`.
